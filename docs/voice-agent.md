# 음성 에이전트 구성 — LLM · STT · TTS · 프롬프팅 · RAG · 사람다운 음성 · 검증

> 버전 v11.0 · 2026-10-14 · PPT 발표 에이전트(pt-agent)의 **음성 에이전트 부분만** 따로 정리한 기술 문서.
> 목적: 구현 영역과 적용 기술을 한곳에 모아, **사람다운 음성 출력과 질의응답 성능을 스스로 검증·최적화**할 수 있게 한다.
> 전체 시스템(계정·PPT 생성·무결 루프 등)은 「시스템 문서」, 모델 교체 절차는 「모델 교체 평가 문서」를 본다.
> 표기: **[실측]** = 로그·측정으로 확인한 값, **[설정]** = 코드·설정에 있는 값, **[미검증]** = 청취·실사용 확인이 더 필요한 항목.

## 1. 한눈에 보는 구성

```
 ┌────────────── 브라우저 (ppt-agent.html) ──────────────┐
 │ 마이크 → Web Speech STT(ko-KR, 연속·중간결과)          │
 │   └ 에코 필터 · 환각 필터 · 의도 판별 · 질문 상태기계  │
 │ 발표 재생기: 문장 큐 · TTS 직렬/동시 큐 · 더킹 · 상태바 │
 └───────┬───────────────────────────────┬───────────────┘
         │ /api/search (RAG)             │ /api/llm · /api/script · /api/tts-openai
   ┌─────▼──────── pt-agent 서버 (Node, :8124) ───────────┐
   │ 임베딩 검색 · 지식 자동 습득 · 의사결정 라우터        │
   │ OpenAI TTS 검증 프록시(/api/tts-openai)               │
   └───┬─────────────┬───────────────┬────────────────────┘
       │ n8n 게이트웨이(웹훅)         │ 로컬 음성 스택
  ┌────▼─────┐   ┌───▼─────┐   ┌─────▼───────────────┐  ┌───────────────┐
  │ 로컬 LLM │   │ OpenAI  │   │ TTS 프록시 :8321    │  │ ASR :8323     │
  │ ollama   │   │ script/ │   │ → mlx-audio :8322   │  │ Qwen3-ASR     │
  │ :11434   │   │ tts/emb │   │ (Qwen3-TTS)         │  │ (검증용)      │
  └──────────┘   └─────────┘   └─────────────────────┘  └───────────────┘
```

| 영역 | 기본(로컬) | 클라우드(관리자 허용 계정만) |
|---|---|---|
| 음성 인식(STT) | 브라우저 Web Speech API(ko-KR, 기본) 또는 **서버 Streaming STT**(VAD+Qwen3-ASR+PT 핫워드, 설정 토글) | — |
| 답변·대본 LLM | qwen3:30b-a3b-instruct-2507 (ollama, n8n `koen_local_llm`) | gpt-4o-mini (n8n `koen_openai_script`) |
| 음성 합성(TTS) | Qwen3-TTS-12Hz-1.7B-CustomVoice (mlx-audio, 기본 목소리 serena) | gpt-4o-mini-tts (n8n `koen_openai_tts_bin`, 기본 nova) |
| 임베딩(RAG) | text-embedding-3-small 1536차원 (n8n `koen_openai_embed`) | 동일 |
| 검증용 ASR | Qwen3-ASR-1.7B-4bit (:8323) — TTS 결과 역검증 | — |

**계정 정책(v10.7)**: 일반 사용자는 승인 시 **로컬 LLM·로컬 TTS 전용**이 기본이다. 관리자가 승인 폼에서 "OpenAI"를 체크한 계정만 클라우드 LLM·TTS를 쓴다. 미허용 계정은 화면(`window.__USER_PERM__`)과 서버(`/api/script`, `/api/tts-openai` 403) 양쪽에서 막힌다. **주의**: 임베딩은 현재 모든 계정이 OpenAI 임베딩 API를 거친다(문서 청크·질문 텍스트가 외부로 나감) — 완전 로컬을 요구하면 로컬 임베딩 모델 교체가 필요하다([미해결]).

## 2. STT — 음성 인식과 질문 개입(바지-인)

### 2.1 인식기
- **브라우저 Web Speech API**: `lang='ko-KR'`, `continuous=true`, `interimResults=true`. 최종 결과(final)로 질문을 접수하고, 중간 결과(interim)는 **볼륨 더킹의 조기 신호**로만 쓴다.
- **침묵 감시자**: 인식기가 `onend/onerror` 없이 죽는 경우를 위해 12초간 이벤트가 없으면 인식기를 강제 재기동한다(로그 `⚠ STT 감시`). **[실측]** 호스트가 과부하일 때 이 로그가 빈발하며 질문 인식이 늦어진다.
- 서버측 **Qwen3-ASR-1.7B-4bit(:8323)**: 사용자의 마이크 입력용이 아니라 **TTS 출력 검증용**(§4.4, §4.6). 한글 숫자 verbatim, 웜 100~230ms **[실측]**. 대체 후보 whisper large-v3-turbo(:8782).

### 2.1b 서버 Streaming STT (v11.0, 설정 🎙 "서버 (핫워드)")
`마이크(AEC·NS 켬) → AudioWorklet 16kHz PCM16 100ms 청크 → POST /api/stt/chunk → 서버 VAD → Qwen3-ASR(context=핫워드) → 핫워드 보정 → 이벤트(speech_start/partial/final)`
- **전송**: WebSocket 대신 HTTP 청크 POST — 응답에 쌓인 이벤트를 실어 보낸다(frp→nginx 체인에 Upgrade 설정 불필요). 5초 이상 밀린 청크는 폐기해 지연 상한을 둔다.
- **VAD**(`lib/stt_stream.js`): 20ms 프레임 에너지, 적응형 잡음 바닥(×3.5 진입 / ×2.2 이탈), 시작 80ms 연속·종료 무음 900ms·선행 300ms 보존, 300ms 미만은 잡음 폐기, 20초 강제 종결.
- **부분/최종**: 발화 시작 약 250ms 뒤 첫 부분 인식, 이후 500ms 간격(중간결과 → 더킹·자막·조기 인지). 최종만 질문 파이프라인에 들어간다.
- **PT 핫워드**: 클라이언트가 슬라이드 제목·영문 약어를 추출(최대 180개) + 서버가 발음 사전·문서 어휘(IoT, BLE, KPI, L1…)를 합친다. ① **ASR `context` 편향**(Qwen3-ASR 시스템 프롬프트 — `voice-agent/stt_server.py`에 선택 필드 추가, 없으면 기존과 동일) ② **퍼지 보정**: 띄어쓰기·영문 한글 독음("아이오티"→IoT, "엘삼"→L3, "범 정부 아이 공통 기반"→"범정부 AI 공통기반")은 조용히 적용, 철자 교정("위저베이스"→"위즈베이스")은 기존 **"…를 말씀하신 건가요?" 확인 질문** 경로로 넘긴다. 사용자가 쓴 일반 어휘("블루투스", "아이")는 치환하지 않는다. **컨텍스트 누출 방어**: 짧은 부분 인식(<1초)에서 모델이 핫워드 목록을 되읊는 현상을 실측으로 발견 → 핫워드 3개 이상이 쉼표로 나열된 전사는 폐기.
- **재사용**: 서버 최종 결과는 `recognizer.onresult`와 같은 모양으로 주입돼 `isHall`·중복 final·`isEcho`·`stripEchoPrefix`·`cleanQuestionText`·`RESUME_CMD_RE`·발음 사전·퍼지 교정이 그대로 적용된다(필터·상태기계 분기 없음).
- **장애 대응**: 청크 전송 3연속 실패·세션 소실(404)·시작 실패 → 재연결 2회(1s, 2s) → Web Speech 폴백(`qa_log`에 `stt_server_issue`/`stt_fallback_web`, 사용자 화면 무노출).
- **한계**: Qwen3-ASR는 단어 신뢰도를 주지 않는다 → "불확실" 판정은 핫워드 퍼지 교정 여부로 대체. 브라우저 마이크 캡처(getUserMedia/AudioWorklet)는 실제 마이크로 검증이 필요하다(합성 음성으로 서버·프로토콜만 검증됨).

### 2.2 입력 정제 필터 (질문이 아닌 소리를 걸러냄)
| 필터 | 목적 | 핵심 규칙 |
|---|---|---|
| 환각 필터 `isHall` | 무음 구간 ASR 환각("MBC 뉴스입니다", "구독과 좋아요") | 방송사·구독 문구 정규식 폐기 |
| 중복 파이널 폐기 | ASR이 같은 발화를 2회 방출(14ms 간격 **[실측]**) | 2.5초 내 동일 텍스트 사본 폐기 |
| **에코 필터 `isEcho`** | 에이전트 자기 음성이 마이크로 되먹여 질문으로 오인 | 최근 발화 `_recentSpoken`(윈도우 8~10개, 정규화 버전 포함 — 공백·문장부호 제거, 한글화 변환본 병행) 대비 내용 일치·접두 일치 판정, 내레이션 꼬리+사용자 발화 합침은 **접두 절단**(`stripEchoPrefix`)으로 질문 본문만 남김 |
| 진행 명령 게이트 | "계속 발표할까요"가 질문으로 습득되는 오염 | `RESUME_CMD_RE` — 재개 명령으로 처리 |
| 파편 게이트 | 8자 미만 에코 파편 | 발표 중 폐기 |
| 질문 정리 `cleanQuestionText` | 트리거 문구("질문 있습니다")가 질문에 합쳐짐 | 트리거 변형 제거, 4자 미만 폐기 |

### 2.3 질문 개입 흐름 (상태기계 `qaState`)
`playing → (트리거/의도 감지) → waiting_question("질문해 주세요.") → answering → (답변 후) resume 확인 → playing`
- **의도 판별 `detectIntent`**: `INTENT_RE`(질문·잠깐·멈춰·정지 등)로 질문 개입을 즉시 인지, "OpenAI에게 질문 있습니다"처럼 호칭이 붙은 트리거는 `_askOnly` 정규식으로 트리거 문구를 보존해 **"질문해 주세요."** 응답으로 분기한다.
- **종료 Q&A**: 마지막 슬라이드 뒤 "제가 준비한 발표 자료는 여기까지입니다. 질문 있으신가요?"만 말하고 **6초 대기**(사용자 음성이 감지되면 12초까지 연장, 답변 뒤 추가 질문은 10초 대기) → 없으면 "더 이상 질문이 없으시면 제 발표는 마치겠습니다. 경청해 주셔서 감사합니다."로 마무리. 상수: `CLOSING_WAIT_MS=6000`, `CLOSING_AFTER_ANSWER_MS=10000`.
- **볼륨 더킹(에코 근본 차단)**: 재생 중 사용자 발화로 보이는 **중간 결과**가 오면 출력 볼륨 1.0→**0.7**, 질문 접수 확정 시 **0.5**, 답변 시작·재개 시 **즉시 1.0 복귀**. Web Audio `GainNode` + `setTargetAtTime`(내림 0.03s / 올림 0.12s)로 클릭음 없이 램프, iOS Safari는 AudioContext 잠금 해제 후 `createMediaElementSource`로 라우팅.

## 3. LLM — 모델·호출·지연 설계

### 3.1 모델 구성 **[설정]**
| 용도 | 경로 | 모델/옵션 |
|---|---|---|
| 질의응답(기본) | n8n `koen_local_llm` → ollama | qwen3:30b-a3b-instruct-2507-q4_K_M, `num_ctx 8192`, `temperature 0.1`, `think:false`, `keep_alive 3m` — 90 tok/s **[실측]** |
| 대본 생성·최신성 질문(허용 계정) | n8n `koen_openai_script` | gpt-4o-mini, `temperature 0.7`, `max_tokens 1000` |
| 지식 자동 습득 | 서버 → `koen_openai_script` | 거절 질문을 클라우드가 답해 로컬 RAG에 임베딩(§5.5) |
| 라우팅 판정(섀도) | TypeSafe Jev(`decision/`) | rule 라우터가 실권, Jev는 대조만(§3.4) |

모델 선택은 n8n 게이트웨이가 단일 진실원이다(`ppt-agent.html`은 model 필드를 보내지 않음). 모델 교체는 「모델 교체 평가」 모듈(HF 조사→실측 벤치→무수정 시험 전환→승인/롤백)로만 한다.

### 3.1b Conversation Manager (v11.0) — 맥락·후속질문
- **메모리 3계층**: ① 단기 대화(최근 5턴: 원문·재작성·대화행위·답변 400자) ② 세션 요약(5턴 초과분을 한 줄씩 압축, 최대 8줄) ③ 발표 메모리(현재 슬라이드/문장, 중단 위치 `슬라이드:문장`, 이미 설명한 장표 제목, 곧 설명할 장표 제목 — 렌더 상태에서 파생해 별도 저장·불일치 없음). 발표 시작 시 초기화.
- **대화행위**(규칙 판정, LLM 호출 없음): QUESTION / FOLLOW_UP(지시어·생략형) / CLARIFICATION / COMPARE / DETAIL / SUMMARY / REPEAT / CORRECTION. 행위별 답변 규칙이 프롬프트에 붙는다("핵심만 두 가지로…", "앞에서 설명드린 내용과 비교하면…" 등). REPEAT·SUMMARY·FOLLOW_UP 계열은 직전 답변을 근거 자료로 허용(이미 검증된 내용만 재사용).
- **후속질문 재작성**: 지시어("그거·그 부분·그러면·아까·방금…")·짧은 의문사형·"~는요?" 생략형일 때만 로컬 LLM 1회(≤3초, 타임아웃/실패 시 직전 질문 앵커 규칙 재작성) — 독립 질문이면 호출하지 않는다. 결과는 질문 원문과 함께 보존(`raw_query`/`rewritten`), 검색·검증은 재작성본, 컨텍스트 [현재 질문]은 원문.
- **장표 참조**: "5페이지/오 장표" → 해당 장표 제목·대본 일부를 [참조 장표 N]로 주입하고 검색 질의에 장표 제목을 덧붙인다.
- **해석 불가**: 지시어뿐(≤14자)이고 이을 대화도 없으면 추정하지 않고 "어떤 부분을 말씀하시는 건지 조금 더 구체적으로 말씀해 주시겠어요?"로 되묻는다.
- **재개 문구**: 질문 답변 뒤 재개 시 고정 템플릿 3종(주제가 곧 나올 장표와 겹치면 "뒤쪽 장표에서도 다시 설명드리겠습니다", 앞서 설명한 내용과 겹치면 "앞서 말씀드린 내용과 연결되는 부분입니다", 기본 "질문하신 부분까지 설명드렸습니다") — 프리캐시, LLM 지연 없음. 재개 위치는 끊긴 문장의 처음부터(`qaLog('resume',{loc})`로 기록).

### 3.2 지연 숨기기 (사람처럼 반응하는 체감 설계)
질문 접수 즉시 **3중 병렬 체인**을 돌린다.
1. **추임새 즉시 재생**(프리캐시 0ms) — "확인해 보겠습니다", "알겠습니다, 잠시만요." 등 **중립 멘트만**(의사·답변 약속 금지). "답변드릴게요"는 실제 답변 직전에 **1회만**.
2. **RAG 검색**(예산 2.5초, 초과 시 참조 없이 진행·`ragTimeout` 기록).
3. **LLM 답변 생성** — 늦으면 시간벌기 멘트(프리캐시 2종).
- 답변 텍스트는 즉시 화면에 표시, 음성은 20초 예산(초과 시 잔여 큐 폐기 + "답변은 화면에 표시되어 있습니다").
- **AI 상태바(화면 하단)**: 🔎 검색 중 / 💭 답변 준비 / 🔊 다음 내용 준비(k/n)를 경과 초와 함께 표시(`aiBusy/aiBusyEnd`, 45초 만료) — 대기가 길어져도 "멈춘 것 같다"는 불안을 없앤다.

### 3.3 환각 방지(핵심 원칙: 근거 없으면 말하지 않는다)
- **고정 거절 문구**: "관련 정보가 없어서 지금은 제가 답변드릴 수 없습니다." — **LLM이 거절 문장을 만들지 않는다**. LLM은 정확히 `[[NO_ANSWER]]` 토큰만 내고, 클라이언트가 상수 문구로 교체(`NO_INFO_MSG`).
- **3순위 프롬프트(`buildAnswerCtx`)**: ① 참고 자료·슬라이드·발표 중 문장에 근거가 있으면 그 내용만(자료에 없는 수치·날짜·고유명사 금지, 출처·파일명 언급 금지, 끝에 `[근거:자료N]`) ② 자료에 없지만 널리 알려진 일반 상식·용어 정의는 `[근거:일반]` ③ 근거 불명확·확신 없음 → `[[NO_ANSWER]]`. 사내 사실(인원·실적·일정·계약)과 시의성 정보(뉴스·시세·날씨·출시일)는 일반 지식으로 답하지 않는다.
- **클라이언트 근거 게이트 `verifyAnswer`(문장 단위)**: 모델이 붙인 근거 태그를 믿지 않고 문장마다 재검증한다.
  - 자료 문장: 숫자·영문 토큰이 자료에 실존 **그리고** 한글 2-gram 겹침 ≥ 0.35(`groundedIn`).
  - 일반 문장: `allowGen`(일반 태그·refs 0건·정의형 질문) + `_generalSentenceOk`(내부 어휘·시의성·**질문에 없던 새 숫자 없음**) 통과 시에만 허용, 첫 일반 문장 앞에 "일반적인 상식으로 말씀드리면, " 삽입.
  - 폐기 문장만 남으면 전체 거절. 자동 습득 지식 기반이면 "클라우드 AI로 보강한 참고 정보(검증 전) 기준으로 말씀드리면, " 접두(첨부 문서는 접두 없음 — 내장 지식).
- **재판정 1회**: 수동 문서 refs가 있는데 1차 판정이 실패하면 [재판정 지시]를 붙여 한 번 더 생성(자료에 있는 내용이 거절되는 오탐 방지).
- **파라메트릭 직답**: refs 0건이라도 `parametricAnswerable`(사내 고유 사실 아님)이면 참조 없이 로컬 LLM이 잘 알려진 사실만 직답, 확신 없으면 `[[NO_ANSWER]]` → 거절/습득 경로로 낙하.
- **휘발성 질문**(오늘 날씨·시각·환율·시세 등 `VOLATILE_RE`)은 RAG·습득 대상이 아니며 전용 즉답 경로(`/api/volatile`, Open-Meteo+KST)로 답한다.

### 3.4 의사결정 라우터(Jev, 섀도 모드)
rule 기반 라우터가 route(로컬 RAG / 클라우드 / 거절 등)를 결정하고, 상용 TypeSafe Jev를 **병렬 섀도**로 호출해 일치율·지연·토큰 비용을 `eval/decision_log.jsonl`에 쌓는다. 배터리 55샘플 일치 42%, p50 204ms, 1k토큰/콜 **[실측]** → 실권은 rule 유지, 라이브 축적 후 채용 판정.

### 3.5 톤(말투) 프롬프트
스크립트·답변 프롬프트에 공통으로 "**항상 차분하고 친절한 존댓말, 한 문장은 짧게, 감탄사·느낌표 금지, 질문형 문장 금지**"를 넣는다. TTS가 문장 길이·기호에 민감하므로 LLM 단계에서 먼저 낭독 친화적으로 쓰게 하는 것이 목적이다(§4.5 문장 부호 정규화와 짝).

## 4. TTS — 음성 합성 (로컬 + OpenAI)

### 4.1 로컬 경로
`브라우저 → https://bc.wizbase.ai.kr/tts-api/v1/audio/speech(nginx) → mlx_tts_proxy :8321 → mlx-audio :8322 (Qwen3-TTS-12Hz-1.7B-CustomVoice-bf16)` (OpenAI 경로만 서버 `/api/tts-openai` → n8n `koen_openai_tts_bin`)
- 요청 본문: `voice`(기본 **serena**), `language:'ko'`, `response_format:'wav'`, `instruct`(STYLE).
- **STYLE 지시**: "Warm and friendly Korean presenter speaking with a gentle smile. Bright, pleasant and clear voice. Calm, moderate pace. Polite and confident. Read English words… with Korean-style English pronunciation." — 대안 문구들과 비교해 **현재 STYLE이 가장 안정적**이었다 **[실측]**. 남성 보이스는 `styleFor()`가 성별 문구를 치환(여성 지시를 남성에 쓰면 갈라짐).

### 4.2 프록시 방어 계층 (모델·서버 무수정 보호)
mlx-audio의 두 근본 결함(동시 요청 GPU 경합, EOS 미생성)을 프록시가 감싼다.
1. **전역 락 직렬화** — 동시 요청 시 무한 행·96초 무음 방지(스트림 본문까지 락 안에서 소비).
2. **문장 분할**(`[.!?…]` 경계, 4자 미만 병합) + 조각별 `max_tokens` 상한(자×2.8+100).
3. **길이 게이트**: floor(조기 종료 = 반 단어) / cap(과잉 생성 = runaway) 판정 + trailing 무음 절단. 정책 `tts_policy.json`(v8): `attempts 3`, `temp_ladder [0.15,0.15]`, `floor_mult 1`, `cap_mult 1.08` — 무결 감시자가 로그를 읽어 클램프 범위 안에서만 자동 조정.
4. **실패 시**: 열거 접미사 재작성('첫째,'→'첫 번째,') → 조각 2분할 재귀 → 최종 실패만 502.
5. **클라이언트 단절 취소**: 0.3초 폴링으로 단절을 감지해 좀비 생성이 락을 쥐지 않게 한다.
6. **재시도 지연**: 429/5xx는 1.2초 후 재시도.

### 4.3 목소리 일관성(톤·화자 드리프트 근본 대책)
| 대책 | 내용 |
|---|---|
| **시드 고정** | qwen3 CustomVoice 샘플링이 시드 없이 돌아 호출마다 화자가 흔들림이 근본 원인 → 시드 **29** 고정(site-packages 패치 3곳, **pip 업그레이드 시 소실 주의**). 프록시는 **1차 시도만 고정**, 재시도는 변주(실패 경로 탈출) |
| 샘플링 고정 | `temperature 0.15`, `repetition_penalty 1.15`(EOS grind 33~39% → 0건 **[실측]**), 사다리 고정 |
| 보이스·스타일 고정 | 요청마다 같은 voice·STYLE. 폴백 보이스를 **serena로 통일**(남성 dylan 폴백이 여성 지시와 충돌해 갈라짐·다른 목소리 유발) |
| **음향 게이트** | 생성 직후 WAV에서 F0(자기상관), 스펙트럼 평탄도, 유성 비율, 피치 단절률, RMS를 계산해 **음성별 정상 대역**(`tts_acoustic_bands.json`: serena·sohee·vivian·dylan·uncle_fu)과 비교 — 벗어나면 시드를 바꿔 재생성(최대 attempts), 마지막 시도는 경고 수락(무음 방지). 실측: 잘못된 성별 보이스 dylan 22/24 포착, serena 70샘플 F0 중앙값 220~316Hz 이상치 0 |
| **언어 역검증** | qwen3가 `language` 파라미터를 무시해 한국어가 중국어 발음으로 나오는 사고 → 짧은 답변류는 ASR 역검증, 한글 비율 35% 미만이면 시드 제거+temp 0.3 재생성(fail-open) |
| 짧은 꼬리 청크 | 3자 미만 조각 병합(운율 붕괴 방지) |
| 로그 신호 | `ACOUSTIC-REJECT`, `ACOUSTIC-WARN-ACCEPT`(`bc-ai/mlx-tts-proxy.log`) |

### 4.4 OpenAI 경로와 서버 검증 프록시(`/api/tts-openai`)
- 모델 **gpt-4o-mini-tts** + 한국어 `instructions`("한국어 표준 발음으로 또박또박… 입력된 글자만 그대로 읽고 단어를 덧붙이거나 빼거나 바꾸지 않습니다. 영어 약어와 숫자는 한국어 화자가 말하듯…"). 보이스: alloy·echo·fable·onyx·nova·shimmer(기본 nova).
- 서버가 n8n 결과를 받아 **로컬 ASR로 되받아쓰기** 후 판정:
  - 일반 문장: 한글 2-gram **재현율 ≥ 0.75**(영문·숫자 토큰은 면제), 미달 시 최대 3회 재생성, 최선 결과 채택.
  - **고정 문구(40자 이하)**: 한글 **완전 일치**(최대 5회) + 재현율 ≥ 0.9이면 `data/tts-cache/<sha1(voice\ninput)>.wav`에 **결정적 캐시** — 이후 같은 문구는 항상 같은 음원.
  - 응답 헤더 `X-TTS-Source`(gen/cache), `X-TTS-Recall`, `X-TTS-Ms`; 재생성 로그 `[TTS-OPENAI 재생성]`.
- **한계 [미검증]**: ASR은 "다른"과 "타른"처럼 청각상 이질적인 발음도 같은 글자로 받아쓸 수 있다. 그래서 고정 문구는 **문두 파열음 완충**(예: "혹시 다른 질문 없으시면…")처럼 발음 위험 지점을 문구 설계로 피한다 — 최종 판정은 사람이 듣는 것이다(§7.3).
- 속도: n8n은 속도 1.0 고정이므로 **클라이언트 `playbackRate`**로 조절(로컬·OpenAI 공통).

### 4.5 낭독 전처리 (`ttsNormalize` → `koNizeTts` → 입력 단위 정리)
- **숫자·단위**: 한자어 수(년·월·일·분·초·원·%)와 고유어 수(시·개·명·번째 등)를 단위별로 구분해 한글로 풀고, 범위 `~`, 시각·날짜·소수를 규칙화. 단위 공백은 화이트리스트(`_UNIT_SP`)만.
- **약어·고유명사 사전 `_KONIZE_TABLE`**: IoT→아이오티, AIoT→에이아이오티, SSOT→에스소트, RBAC→알비에이씨, MCP→엠씨피, WIZBASE→위즈베이스 등 — 영문이 영어식·중국어식으로 새는 것을 차단.
- **문장 부호 정규화**: 말줄임·중복 부호·괄호 정리, 마지막에 마침표 보장(OpenAI 경로 `ttsPrepareOpenAi`) — 종결 억양 일관.
- **사전 한글화 로그**: `TTS 한글화 N건: AI,AI` 형태로 치환 내역을 서버 로그에 남겨 검증 가능.

### 4.6 재생·큐 설계 (끊김·무음 방지)
- 문장 단위 **프리페치**: 발표 시작 시 고정 멘트 전체(`CACHED_PHRASES`: "질문해 주세요.", "다른 질문 없으시면…", NO_INFO 문구, 종료 멘트 등)를 먼저 생성해 질의응답 중 **0ms 재생**.
- 로컬은 **직렬 큐**(GPU 경합 방지), OpenAI는 **동시 3**. 큐 잡마다 `AbortController` — 질문 진입 시 프리페치만, 답변 잔여는 `qa`만, 정지는 전부 즉시 폐기(인플라이트 포함).
- **답변 조각 순서 보장**: 조각 i를 인덱스 위치에 저장하고 순서대로 대기(v10.3에서 역순 배열 버그 수정). 늦으면 상태바 표시, 1회 재생성 후 건너뛰고 `answer_part_skipped` 로그.
- 오디오 잠금 해제: 발표 시작 제스처 안에서 무음 WAV + AudioContext resume.

## 5. RAG — 첨부 문서 지식과 자동 습득

### 5.1 인덱싱
- **청킹**(`lib/chunk.js`, v11.0): 마크다운 헤딩(#~###) 기준 1차 분할 → 800자 초과 시 구조 단위(문장·목록 항목·표 행)로 2차 분할, **겹침 120자**, 이어지는 조각 머리에 **헤딩 재부착**, 표는 머리글 재부착·행 구조 보존, 청크 메타(`chunks.meta`: title/section/slide_no/part) 저장, 20자 미만 조각 폐기, **제목만 있는 80자 미만 조각은 다음 내용과 병합**(제목 매칭이 검색 상위를 독점하던 문제 **[실측]**).
- **임베딩**: text-embedding-3-small(1536차원) — n8n 게이트웨이 경유, SQLite `chunks.embedding`에 BLOB 저장.
- 문서 범위: '주로 참고' 지정 문서 + **자동 습득 문서(origin='auto')는 항상 검색 대상**.

### 5.2 검색·랭킹 (`/api/search`) — v11.0 Hybrid
`질문(재작성본) → 발음 교정 → [Dense: 코사인×신뢰도 가중] + [BM25: 한글 2-gram·영문/숫자 토큰] → 후보 풀(각 상위 20) min-max 정규화 후 0.45·Dense+0.55·BM25 융합 → 특징 재랭커(융합 점수 차 ≤0.02일 때 타이브레이크) → 상대 컷(융합 ≥ 최고의 45%, 코사인 가중 ≥0.25 또는 BM25 정규화 ≥0.3) → 상위 k(기본 4)`
- 프로젝트 필터: 요청 `project`와 다른 프로젝트 문서는 ×0.5 감쇠(질문에 그 프로젝트 이름이 있으면 해제, 프로젝트 미지정 문서는 공용).
- 응답 `refs[*]`: `chunk_id, seq, slide_no, title, relevance(융합), rerank_score, tier(A/B/C), source_type(official/verified/auto), project` + 호환용 `score`. `trace`에 dense/BM25/융합/재랭크/최종 청크 id·점수.
- 자료 계층: A=수동 등록(공식), B=자동 습득이지만 신뢰도 1.0(관리자 수정·승인), C=자동 습득(참고용). 계약·일정·비용·인원 등 공식 사실 질문(`OFFICIAL_Q_RE`)에는 Tier C를 쓰지 않는다.
- **이전 방식**(참고): 코사인×신뢰도 가중×(1+0.25×질문 2-gram 어휘 비율), 상대 컷 top×0.85, 상위 3.
1. 질문 교정(§5.3) → 질문 임베딩.
2. 점수 = `코사인 × (0.6 + 0.4 × 신뢰도)` × `(1 + 0.25 × 질문 2-gram이 청크 본문에 등장한 비율)`.
   - 신뢰도: 수동 문서 1.0 / 자동 확신 0.5 / 자동 불확실 0.3 → 가중 ×1.0 / ×0.8 / ×0.72.
3. **컷**: `max(0.25, top×0.85)` — 이 임베딩은 무관 쌍도 배경 유사도가 높아(무작위 쌍 중앙값 0.462, p90 0.641 **[실측]**) 절대 임계값이 아니라 **상대 컷+낮은 바닥**을 쓴다. 상위 k(기본 3)만 반환.
4. 클라이언트는 점수로 거절하지 않는다(관련·무관이 점수로 구분되지 않음 — SSOT 정답 0.376 vs 무관 0.374 **[실측]**). **관련성 판정은 LLM의 `[[NO_ANSWER]]` + 문장 단위 검증**이 맡는다.

### 5.3 발음·오타 교정(ASR 오인식 대응) — 3층
① **발음 사전** `data/pron-dict.json`(운영자 편집, 부분문자열 치환이라 조사 안전; 위즈베이스는 오탐 스팸 방지로 일부러 WIZBASE 미등록) → ② **청크 어휘 퍼지 교정**(어휘에 없는 3음절+ 토큰을 동일 길이·1음절 차이·유일 후보일 때만 교정, **마지막 음절 차이는 조사 변이라 제외**) → ③ **2-gram 가점**. 의심되면 **1회 확인 질문**("…를 말씀하신 건가요?", `pron_confirm` 상태, "아니요"면 `noCorrect`로 원문 재검색).

### 5.4 답변 생성에 들어가는 컨텍스트
`buildAnswerCtx`: 현재 슬라이드 제목 + 발표 중이던 문장 + 질문 + 참고 자료 최대 3개(각 800자 절단, 자동 지식은 "(자동 학습·검증 전)" 표기). 첨부 문서는 **내장 지식**이므로 답변에서 문서명·출처를 말하지 않는다.

### 5.5 지식 자동 습득 폐루프 (RAG 자기성장)
`로컬 거절(rag-miss) → 서버가 클라우드 LLM으로 답 생성 → 품질 게이트 → origin='auto' 문서로 임베딩 → 25초 후 재검색 → 가능해지면 "추가 확인이 완료되었습니다"`
- **습득 품질 게이트**: 존댓말 어미 또는 영문 용어 필수, 사과-선두 장문 거절 차단, 질문 에코 합본 청크 금지(답변-only 청크), 4자 미만 질문 폐기, 휘발성 질문 습득 금지.
- **오염 방어**: 질문 에코가 검색 점수를 독점해 진짜 문서를 밀어내는 사고를 막기 위해 비답변 게이트·`니까` 어미 차단 등(실측으로 발견·수정).
- **관리자 콘솔 🧠 지식 관리**: 미답변 질문 목록(관련도 라벨 높음/경계/낮음), 지식 리스트, 전문 수정(재청크·전체 재임베딩, 임베딩 선성공 후 트랜잭션 치환), 신뢰도 조정, 일괄 삭제(재습득 제외 등록).
- **지연 답변**: 습득이 오래 걸리면 통보→발표 재개→문장 경계에서 제안→동의 시 답변(동의 유예 30초, 1회 재제안).

### 7.2 정량 지표와 합격선(권장)
| 영역 | 지표 | 측정 | 정상 범위 |
|---|---|---|---|
| TTS 지연 | 짧은 문구 생성 시간 | 프록시 `OK … elapsed=` | **1~2초**, 5초 초과가 반복되면 호스트 부하 점검 |
| TTS 안정 | 음향 거절률 | `ACOUSTIC-REJECT` ÷ `REQ` | 낮을수록 좋음(10~20%면 재생성 비용 증가 — 대역 재조정 검토) |
| TTS 정확도 | OpenAI 재현율 | `X-TTS-Recall` | ≥ 0.75(고정 문구 ≥ 0.9 + 완전 일치) |
| TTS 완결 | 절단·runaway | `TRUNC`, `RUNAWAY` 건수, `answer_part_skipped` | 0에 수렴 |
| STT 반응 | 질문 접수 지연 | `🎙` 시각 → `ask` 로그 시각 | 1~2초 |
| STT 건강 | 무이벤트 재기동 빈도 | `⚠ STT 감시` | 침묵 중 15초 주기는 정상, **발화 중 발생은 부하·마이크 문제** |
| 에코 | 에코 오접수 | `🔇 에코 무시` 대비 오접수 질문 | 오접수 0 |

| RAG | 적중률 | 질문 세트 대비 `ragRefs>0` 비율, `ragTop` 분포 | 도메인 질문 세트에서 정답 청크가 top-3에 포함 |
| 지연 | 답변 총지연 | `ragMs + llmMs + 음성 준비` | 첫 음성(추임새) 0.5초 이내, 본 답변 시작 수 초 내 |

### 7.3 사람 청취 검증 절차 (자동 지표가 못 잡는 부분)
1. **고정 문구 10종**(질문해 주세요 / 혹시 다른 질문 없으시면… / 관련 정보가 없어서… / 종료 멘트 등)을 각 목소리(serena, nova)로 3회씩 재생 — 발음 꼬임(예: "타른")·톤 변화·끊김 체크.
2. **톤 드리프트**: 같은 발표를 연속 3회 재생해 밝은→슬픈 톤, 목갈라짐, 다른 목소리 발생 여부 기록(발생 시각을 프록시 로그 `ACOUSTIC-*`와 대조).
3. **끼어들기 시나리오**: 발표 중 "질문 있습니다" → "질문해 주세요." → 질문 → 답변 → "계속 발표" 전 구간에서 에코 오접수·볼륨 복귀·무음 구간 확인.
4. **무근거 질문 세트**: 자료에 없는 사내 사실(실적·인원), 최신 뉴스, 날씨, 일반 용어 정의를 섞어 질문해 ① 고정 거절 ② 일반 상식 접두 ③ 휘발성 즉답이 기대대로 분기되는지 확인(`verifyWhy`·`source`로 근거 추적).
5. **RAG 중심 질문 세트**: 첨부 문서 안의 문장을 바꿔 묻는 질문(예: "기존 IoT는 어떻게 되는 건가요?")이 **반드시 답변**되는지 — 거절되면 qa_log의 `firstRaw/firstWhy/retried`로 원인(검색 vs 검증) 분리.

### 7.5 알려진 한계·주의
- **호스트 부하**: 스왑 포화·다른 LLM/VM 동시 구동 시 TTS가 3~8초로 느려지고 STT 감시 재기동이 빈발 — 질문 개입 인식 저하의 1차 원인으로 실측 **[실측 2026-10-14]**.
- **임베딩 외부 전송**: OpenAI 임베딩 사용(§1).
- **청취 미검증 항목**: OpenAI nova의 "혹시 다른 질문 없으시면…" 발음, 로컬 serena의 장시간 음색 일관성은 ASR·음향 지표로만 확인됨.
- Web Speech STT는 브라우저(Chrome 계열)·네트워크 상태에 의존하며 서버에서 성능을 제어할 수 없다 — 더 강한 제어가 필요하면 서버 STT(Qwen3-ASR) 스트리밍 전환을 검토.
- 로컬 LLM은 90 tok/s 수준이며 답변 2~3문장 기준 지연이 수 초 — 추임새·상태바로 체감 지연을 줄이는 설계에 의존한다.

### 8.2 Hybrid RAG — 100문항 평가셋
평가셋 `battery/rag_evalset.json`(직접 25·표현 변형 25·후속 20·고유명사 10·숫자 10·근거 없음 10), 대상 = 수동 등록 Q&A 문서(53청크). 정답 = 해당 주제 청크(seq) 집합. 표현 변형·후속 질문은 LLM이 **답변 내용만 보고** 제목·키워드 단어를 피해 생성(원문 복사 방지).

| 변형 (답변 가능 90문항) | Recall@3 | Recall@5 | MRR |
|---|---|---|---|
| legacy(Dense+어휘 가점, 이전 방식) | 86.7% | 90.0% | 0.843 |
| dense only | 82.2% | 86.7% | 0.795 |
| BM25 only | 90.0% | 95.6% | 0.880 |
| hybrid(융합) | **93.3%** | **96.7%** | 0.905 |
| hybrid + 특징 재랭커 | 92.2% | 96.7% | 0.896 |
| hybrid + LLM 재랭커(qwen3 30B, +1.1s) | 91.1~93.3% | 95.6~96.7% | 0.84~0.905 |
| **deployed**(서버 `/api/search`와 동일 함수, 컷 포함, k=5) | 92.2% | 95.6% | 0.898 |

- **범주별(deployed)**: 직접 100%/100%, 표현 변형 76%/88%, 후속 95%/95%, 고유명사 100%, 숫자 100%. 지시서 목표 "도메인 질문 Recall@3 ≥ 90%" **달성(92.2%)**.
- **재랭커 결론**: 특징 재랭커·LLM 재랭커 모두 융합 단독 대비 개선이 없었다(±1문항) → 순서는 융합 점수로 정하고 재랭커는 타이브레이크·`rerank_score` 보고로만 쓴다. LLM 재랭커는 지연만 +1.1초라 채택하지 않았다. 잔여 오답(표현 변형 6건)은 질문 자체가 모호해 여러 청크가 정답 후보인 경우가 대부분.
- **융합 가중**: Dense 0.3~0.75 격자에서 0.45가 최상(0.3/0.45/0.6/0.75 → R@3 92.2/93.3/93.3/91.1).
- **근거 없음 10문항**: 검색 점수로는 답변 가능 질문과 분리되지 않는다(상위 Dense 0.20~0.44 vs 0.27~0.67 겹침) — 기존 설계대로 **LLM `[[NO_ANSWER]]`+문장 단위 검증**이 판정한다. 통합 시험(8.4)에서 6/6 거절.
- **한계**: 평가 문서가 1건(Q&A 구조, 청크에 질문·키워드가 이미 들어 있어 BM25에 유리)이다. 지시서의 "공식 수치/날짜 환각 0건"·"Recall@3 ≥ 90%"를 다른 문서 유형(표·긴 산문·PPT 변환본)으로 재확인해야 한다. 자동 습득(Tier C) 문서는 평가에서 제외됐다.

### 8.3 서버 Streaming STT — 합성 음성 실시간 모의
`battery/stt_stream_eval.js`: 서버 TTS(serena)로 만든 도메인 질문 15문장을 100ms 청크로 **실시간 속도**로 흘림(앞 1.0s·뒤 1.6s 무음).

| 조건 | 첫 부분(p50/p90) | 종료→최종(p50/p90) | CER | 도메인 용어(원문/표준표기) |
|---|---|---|---|---|
| 핫워드, 깨끗한 음성 | 602 / 702 ms | 1,082 / 1,222 ms | 0.073 | 11/11 · 11/11 |
| 핫워드, SNR 15dB | 602 / 802 ms | 1,121 / 1,182 ms | 0.056 | 11/11 · 11/11 |
| **핫워드 없음**, SNR 15dB | 602 / 701 ms | 1,042 / 1,183 ms | 0.088 | 9/11 · **7/11** |
- 발화 시작 감지 ≈ 100ms. 지시서 목표: 시작→부분 ≤500ms(**p50 0.6s — 근접, 미달**), 종료→최종 1.0~1.5초(**달성**). 핫워드 적용으로 도메인 용어 표준표기 7/11 → 11/11("법정부→범정부", "오경부→오경보", "돌봄 프로필→돌봄프로필" 교정). HTTP 경로 시험: 세션 시작→청크→이벤트→중지→404 확인.
- **한계(중요)**: ① 입력이 TTS 합성 음성(깨끗·단일 화자)이라 실제 사람 발화·방 반향·다중 화자보다 낙관적이다. ② 브라우저 쪽(getUserMedia·AudioWorklet·재연결·폴백)은 코드 검토·문법 검증만 했고 **실제 마이크로 검증하지 않았다** → 기본값을 🌐 브라우저로 두고 설정에서 켜는 방식으로 배포했다. ③ WER은 측정하지 않고 CER·도메인 용어 적중으로 대체. ④ 에코 오접수율·사용자 발화 누락률은 실발표 로그(`🔇 에코 무시`, `eval/stt_stream.jsonl`)로 측정해야 한다. ⑤ 호스트 부하 시 ASR 지연이 늘어난다(부분 인식은 ASR 사용 중이면 건너뜀).

### 8.4 통합 Q&A 배터리 (`battery/qa_e2e.js`)
실제 `ppt-agent.html` 스크립트를 node vm에서 실행(DOM 스텁)하고 `generateAnswer`를 **실제 서버·로컬 LLM**으로 끝까지 돌린다(음성 출력 제외).
- 직접·용어 질문 8/8 답변(자료 근거, 평균 2~4초), 후속질문 4/4 맥락 연결(재작성 예: "그거 어떻게 검증하나요?" → "재실·외출 확인은 어떻게 검증하나요?", "규모는요?" → "이번 시범사업의 규모는 어떻게 되나요?"), **근거 없는 질문 6/6 거절**(예산·감리업체·주가·인구·시공사·계약금액 — 환각 0건).
- 관찰: "그럼 외부로 나가는 건 없나요?"에 "일반적인 상식으로 말씀드리면…" 접두가 붙었다 — 직전 답변을 근거로 쓰는 문장이 일반 문장으로 분류된 경우. 내용은 자료와 일치하나 접두 표기가 부정확하다(개선 후보).
- **미실시**: 실제 PPT 발표 전체 시나리오, 끼어들기·재개의 음성 구간, 호스트 부하 상황 — 실사용 검증 항목.
